# Native Waylandと共通権限の検証（2026-09-12）

## 対象と変更

Ubuntu 24.04.5 ARM64 / GNOME 46 / Mesa 25.2.8の専用UTM VMで実施。UTM 5.0.5 Beta、virtio-gpu-gl-pci、Apple Core OpenGLの設定は[前回のGPU検証](utm-5.0.5-gpu-2026-09-12.md)を維持。GDMをWaylandへ変更し、`loginctl` のsession typeが `wayland`、`/run/user/1000/wayland-0` が存在することを確認した。GDMとAccountsServiceの変更前設定はゲストの `reports/` に退避した。

共通の `SandboxPolicy`・Permissions保存APIを保ち、Linuxの表示接続をWaylandとX11に分離した。Waylandでは単一ソケットを `/run/mona/wayland-0` に公開し、X11ソケット・認証・環境変数・ホストのsession busを公開しない。Wayland指定が壊れている場合はエラーとし、X11や無制限実行へ切り替えない。

Minecraft 26.2の実JARを `javap` で確認すると、GLXが通常X11を明示選択していた。この版のWayland起動だけに `-DMC_DEBUG_ENABLED=true -DMC_DEBUG_PREFER_WAYLAND=true` を加えた。その他の個別debugフラグは設定していない。将来版やModに同じ内部プロパティが有効とは仮定しない。

## GPUの原因切り分け

サンドボックス外のLWJGL 3.4.1プローブは `GLFW_PLATFORM_WAYLAND` を指定し、OpenGL 3.3 core context、`glfwGetPlatform() == GLFW_PLATFORM_WAYLAND`、`virgl (Apple M4 Pro)`、RGBA 64/128/191/255の読戻しを確認した。

最初のサンドボックス内Wayland起動は画面・音声が動いたが、EGLのdevice information取得に失敗し、llvmpipeへ戻った。libdrmのsysfs参照に合わせ、既に許可しているrender nodeと対応するGPUの識別属性を個別のread-only bindに変更した。ディレクトリと識別用リンクは再構成し、GPUのPCI config/resource、コネクター、sysfs全体は公開しない。primary nodeの識別情報は含むが、`/dev/dri/card*` のデバイスは含まない。

変更後のMinecraftログ:

```text
Using graphics backend OpenGL, using drivers: 4.1 (Core Profile) Mesa 25.2.8-0ubuntu0.24.04.2
Using graphics device: virgl (Apple M4 Pro) (Mesa)
Sound engine started
```

GPU比較では `LIBGL_ALWAYS_SOFTWARE`・OpenGLのバージョン上書きを使用していない。

## 観測

- 本体の起動処理を使うMinecraft 26.2 Vanilla demoをWaylandで120秒実行。タイトル、全画面1280×800、デモワールドをゲストのcompositor画像で確認した。
- UTMのVM指定入力APIでメニューをクリックし、W/Sキーで移動。F3座標が変わり、F11で854×480のウィンドウ表示へ戻ることを確認した。ホストのキーボード・マウスをキャプチャしていない。
- F3には `virgl (Apple M4 Pro)` / OpenGL 4.1と描画が表示された。表示上28〜30 FPSだったが、maxFps=30の短い機能確認であり性能ベンチマークではない。
- 音声エンジン、JavaのPulseAudioストリーム、ナレーター要求とeSpeak開始1・完了1を確認。今回の音声検証はプロセス/ストリームの観測で、新たな人間の聴取確認ではない。
- ナレーターOFFでも30秒実行し、通常音声・GPU初期化を維持したまま、要求なし・speech開始0/完了0を確認した。
- WaylandのネイティブランチャーでもPermissionsの説明文・保存を確認し、ナレーターをONへ戻してPlayから起動。45秒後のJava生存、ゲームのGPU render nodeのFD、Wayland環境のみ・X11 mountなしを確認した。Quit Game後にJavaが終了し、Permissionsの編集とPlayが再び有効になった。
- 同じ最終コードでX11/XWaylandを明示選択した30秒の回帰検証も成功。viewableなウィンドウ、GPU初期化、音声、ナレーター開始1/完了1、プロセス終了を確認した。GNOMEセッション自体はWaylandのまま保持した。
- CLIはWaylandの `window_viewable` を `null` と報告する。X11のxwininfoに相当する汎用の他ウィンドウ可視判定は使わず、graphics初期化と別途のcompositor画像を分けて記録する。

## 権限境界

production backendを呼ぶ `linux_sandbox_probe --wayland` で、RW/RO両設定が成功した。サンドボックス外でアクセス可能なX11のpathname/abstractソケットとsession busを正の対照とし、同じ接続が内部では拒否されることを確認した。

| 観測対象                                                        | サンドボックス内                         |
| --------------------------------------------------------------- | ---------------------------------------- |
| 選択したWaylandソケット                                         | 接続可能                                 |
| X11 pathname / abstract socket、DISPLAY / XAUTHORITY            | 接続不可 / 環境変数なし                  |
| ホストsession bus、任意ホストUnixソケット                       | 接続不可                                 |
| ホスト/他instance/シンボリックリンク経由/子のホスト読み取り     | 拒否                                     |
| 共有ライブラリ読み取り / 書き込み                               | 許可 / 拒否                              |
| ゲーム書き込み                                                  | 設定ON時許可、OFF時拒否                  |
| 専用一時領域                                                    | 書き込み可能                             |
| 直接TCP、IPv4/IPv6 socket、ptrace、追加namespace                | 拒否                                     |
| GPU vendor識別                                                  | 読み取り可能、mountinfoでread-onlyを確認 |
| GPU config、primary device、input device、sysfsネットワーク情報 | 非公開                                   |
| seccomp / no-new-privileges、clone3のENOSYS                     | 確認                                     |
| 呼出元スレッド終了後の生存、監視終了時のdetached子終了          | 成功                                     |

有効な `DISPLAY=:0` と存在しない `WAYLAND_DISPLAY` を同時に渡しても、WaylandソケットのNotFoundで終了した。X11への自動切り替えはしない。

ランチャーUIは `GDK_BACKEND=wayland WEBKIT_DISABLE_DMABUF_RENDERER=1` で起動した。前回同様、WebKit用の回避設定は専用VMだけのものとし、ゲームの環境には継承しない。検証後はゲームを終了し、ナレーターON、Waylandセッションと更新したランチャーを保持する。

## 限界

接続先GNOMEが公開するWayland globalsも確認した。今回のGNOMEではsecurity-context managerはなかった。compositorが提供するプロトコル全体への接続を許し、クリップボードなどの個別権限制御・Flatpak型security-contextによるプロトコル制限は実装していない。他のcompositorで全く同じ隔離保証が得られるという結果ではない。PulseAudioの録音を含むサービス権限も従来どおり。

対象はM4 Proを使うUTMの仮想GPU、GNOME、Minecraft 26.2。物理LinuxのAMD/Intel/NVIDIA、他compositor、他ゲーム版・Mod、長時間安定性、Windowsの実行検証は含まない。
