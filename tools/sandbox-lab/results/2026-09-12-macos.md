# macOS実機検証 — 2026-09-12

## 環境

- macOS 26.1 / build 25B78、Apple M4 Pro、arm64。
- Rust 1.97.1。
- Eclipse Temurin JDK 21.0.7。
- LWJGL 3.3.3、core / GLFW / OpenGLのmacOS arm64 native。
- `sandbox-exec`によるSeatbelt、管理者権限なし。
- stdoutとstderrはパイプで取得。

## 結果

| プロファイル | 対象          | 対照実験             | 隔離実験             |
| ------------ | ------------- | -------------------- | -------------------- |
| 基本         | Rust + 子Rust | 26/26                | 26/26                |
| 基本         | Java + 子Java | 26/26                | 26/26                |
| GUI許可追加  | Rust + 子Rust | 26/26                | 26/26                |
| GUI許可追加  | Java + 子Java | 26/26                | 26/26                |

26件は13操作×2世代。対照実験は制限対象もすべて成功、隔離実験は許可対象のみ成功した。各操作は[README](../README.md)を参照。

GPU描画では両方とも`OpenGL renderer: Apple M4 Pro`、読み戻したピクセルは`rgba=64,128,191,255`、`glError=0`。独立した10回のプロセス実行が期待する判定を満たした。

## 分かったこと

- ファイルメタデータの許可だけでは起動できず、dyld用の`file-read* (literal "/")`が必要だった。追加前はmain到達前にSIGABRTとなった。この失敗を隔離成功と判定していない。
- JVM起動、別JVMの起動、ファイル権限制限、ホストloopbackのTCP/UDP遮断は基本プロファイルで成立した。
- GUIでウィンドウとOpenGLコンテキストだけが作れても、描画成功とは限らなかった。最初のGPU試験は黒いピクセルと`GL_INVALID_FRAMEBUFFER_OPERATION`（1286）で失敗。
- 拒否ログを確認し、GPU関連の`IOGPUGLDrawableUserClient`、`IOGPUSurfaceMTL`などをプロファイルに追加するとframebufferの読み戻しが成功した。最終的な許可集合は[macos-gui.sb](../profiles/macos-gui.sb)に保存した。各許可が単独で必要十分かという最小化試験までは行っていない。
- GUI権限を追加後も、同じファイル・通信の検証を再実行して合格した。
- GUI関連のMachサービスの拒否に伴う警告はstderrに残っている。入力・音声の正常動作を確認するまで、これを「Minecraft向けの権限が揃った」とは扱わない。
